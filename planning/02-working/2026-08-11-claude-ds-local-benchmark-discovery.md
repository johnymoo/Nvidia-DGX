## Design Consequences

- The deployment transition must be a single scripted operation with
  preflight, immutable identity checks, worker-first/head-second startup,
  readiness, receipt capture, rollback, and Qwen restoration.
- The online and local treatments must run with the same Claude Code binary,
  clean task baselines, prompt/tool policy, timeout, and fallback prohibition.
- Primary quality evidence should be executable task acceptance, not a model
  judge. Timing, reliability, tool usage, and token/cost fields can be recorded
  where the provider exposes them.
- Provider identity mismatch or fallback is a benchmark blocker, not a reason
  to silently substitute another provider.

## Confirmed Benchmark Scope

The user confirmed that the comparison is Claude Code end-to-end performance
only. A separate API serving benchmark is out of scope. Raw API TTFT,
inter-token latency, and standalone request throughput are therefore not
acceptance metrics. The benchmark may retain provider-reported timing or token
usage from Claude Code runs as supporting evidence, but it measures completed
coding work rather than the serving layer in isolation.

The user selected a mixed coding-task corpus. It must contain both replayable
tasks representative of the user's private repositories and a bounded subset
of a public SWE benchmark. Results for the private and public strata must be
reported separately before any aggregate is calculated.

The user also required the online `claude_ds` treatment to use the Flash model.
The frozen treatment identities are `deepseek-v4-flash` online and
`deepseek-v4-flash-0731` from the accepted Patch4 GB10 deployment locally.
Both identities must be observed in run evidence, and fallback or a route to
`deepseek-v4-pro` invalidates the affected run.

The first execution is a calibration pilot using public standard tasks only.
The previously discussed full mixed-corpus run count is deferred. The user will
review pilot evidence before deciding whether to add private tasks, repetitions,
or a larger public sample. The current design recommendation is four bounded
SWE-bench Verified tasks, one sequential run per treatment per task.

## Approved User-Story Baseline

Baseline revision: `claude-ds-pilot-r1`

Approval evidence: the user explicitly replied "可以" on 2026-08-11 after the
baseline was presented, and added that execution must be a single script rather
than one test at a time through separately dispatched agents.

- `US-01`: As a GB10 operator, I want to safely offload Qwen and start the
  accepted two-host Patch4 DeepSeek service so that private Claude Code uses the
  exact model, with restoration of the captured Qwen state on startup failure.
  After a successful pilot, DeepSeek remains running and Qwen remains stopped
  until an explicit restore action.
- `US-02`: As a coding-model evaluator, I want the online
  `deepseek-v4-flash` and local Patch4 `deepseek-v4-flash-0731` treatments to
  run under the same Claude Code version, tool policy, task snapshots, and
  timeout, so that four SWE-bench Verified pilot tasks can be compared one
  sequential run per treatment without fallback.
- `US-03`: As a decision maker, I want per-task executable-test outcomes,
  completion state, elapsed time, tool calls, retries, and available token/cost
  evidence so that I can decide whether to expand the corpus or repetitions.

Constraints: no standalone API benchmark; no private tasks in the pilot; do
not alter pdf2md, trading, or lexdata; executable tests are primary quality
evidence; online Pro/default routing and all fallback runs are invalid.

Execution constraint: one validated top-level script owns the complete normal
path. It loops over the frozen tasks and invokes Claude Code subprocesses
directly. The coordinator must not dispatch one implementation agent or one
manual command sequence per benchmark task.

The user subsequently authorized continuous execution without another
confirmation: design the script, run preflight, proceed to the real run when
preflight passes, and repair discovered infrastructure issues before retrying.
