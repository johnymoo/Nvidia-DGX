# R4 Two-Page Benchmark Report Design

Date: 2026-08-12

## Approval And Baseline

Baseline revision: `claude-ds-report-r4`.

Approval evidence: the user explicitly requested that the completed benchmark report be split into two pages, with summary and per-category model commentary on the first page and the complete record on the detail page. The user's standing instruction delegates reversible implementation choices to the recommended default without another confirmation.

- `US-R4-01`: As a benchmark decision maker, I want a concise first page with the overall result and evidence-based commentary for every model in every category so that I can understand the comparison without scanning 47 long task records.
- `US-R4-02`: As a benchmark auditor, I want a separate detail page containing every task, all three answers, scores, and GPT rationale so that I can verify every summary conclusion against the complete record.

| Story | Given | When | Then |
| --- | --- | --- | --- |
| `US-R4-01` | The completed 47-task R3 benchmark | The summary page opens | It shows environment, overall ranking, category scores, and deterministic evidence-based commentary for each model and category |
| `US-R4-02` | The same immutable benchmark artifacts | The detail page opens | It shows 47 tasks, 141 answers, and 47 GPT rationales, with working navigation back to the summary |

Constraints: preserve R3 data, scoring, identities, optional-human-score semantics, and visual language. Both pages must be self-contained static HTML, responsive, and linked in both directions. Commentary may describe only computed score, rank, pass count, and gap evidence; it must not invent causal explanations or statistical superiority.

Non-goals: rerunning candidates or judges, changing benchmark rankings, adding filters or a client framework, and changing the human review workflow.

## Selected Design

The renderer produces sibling files from one immutable input set:

- `index.html`: environment, overall ranking, domain matrix, GPT preference totals, and a model-by-domain commentary matrix. A prominent link opens the complete record.
- `details.html`: task navigation followed by all existing task sections, answer artifacts, score metadata, and GPT rationale. A persistent page switch returns to the summary.

This is preferred over collapsible sections in one document because it materially reduces the initial page size and scan burden while preserving a direct, static audit path. Separate per-domain pages were rejected because they would fragment the evidence and add navigation without reducing the underlying audit workload.

## Commentary Contract

For each model and each domain, compute from the saved result set:

- mean quality score and rank among the three models;
- passed task count over the domain task count;
- score gap to the domain leader;
- strongest and weakest domain for that model.

Text is generated by fixed rules: leader, close second (`gap <= 0.10`), second, or third. The wording states measured outcomes only. Each commentary row links to the first task in that domain on `details.html`.
